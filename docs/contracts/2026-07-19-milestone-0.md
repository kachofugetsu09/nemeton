## 1. Goal

- Objective：实现 `project open -> events -> projection -> inspect -> project replay`，
  且不修改被观察仓库。
- Observable success criteria：以
  [`../design/milestone-0-foundation.md`](../design/milestone-0-foundation.md)
  第 9 节为准。
- Change type：code、schema、docs、CI、repository protection。
- Semantic delta：落实用户确认的 module、平台、目录、Git binding、daemon/API、
  Reality、Artifact、per-Project replay 和下一里程碑 Provider 顺序；不改变 Accepted
  decisions 0003、0004、0006、0007。

## 2. Ownership

- Capability owner：`nemetond` 内的 Project、Event、Store、Artifact 与 API 模块。
- Consumer scope：`nemeton` CLI；future UI 和 Runner 只通过同一 API 消费。
- Authoritative state owner：append-only Project event stream 和其引用的 Artifact。
- Core runtime patch reason：Milestone 0 本身就是 Nemeton 的持久化与 Reality 内核。
- Client-side alternative and rejection reason：CLI 直写 SQLite 会违反唯一逻辑写入者、
  stream revision 和事务不变量。

## 3. Invariants and protected state

- 必须保持的不变量：Project ID 不来自路径；同一 common-dir 只有一个 Project；
  event append-only；投影可重建；replay 无外部副作用；dirty 正文不进入 Reality；
  daemon 是唯一 SQLite writer。
- 允许增加的持久化状态：Go 源码、migration、测试、文档；运行时数据目录中的
  SQLite、Artifact、migration backup、lock 和 socket。
- 允许更新或逻辑失效的状态：Project binding、current Reality、projection state、
  maintenance/ready 运行状态。
- 禁止物理删除的状态：domain events、project stream 历史、被引用 Artifact、用户
  checkout 和用户 Git history。Project replay 只可事务内重建派生投影。
- 受保护资源：`/mnt/data/coding/nemeton` 主 checkout、所有被观察目标仓库、用户凭据、
  现有进程和仓库外非测试数据库。

## 5. Side effects

| 边界 | 允许的副作用 | 明确禁止 |
| --- | --- | --- |
| 文件 | 隔离 worktree、构建缓存、临时测试目录、应用数据目录 | 修改用户目标仓库 |
| Git | branch、worktree、commit、push、PR、merge | force-push、改写历史、删除用户分支 |
| 数据库 | 测试库；运行时 events/projections；迁移前 backup | 删除事件、绕过 daemon 写库 |
| 进程 | 测试 daemon、只读 Git 子进程 | 后台安装、systemd、launchd |
| 网络与外部 API | 下载锁定 Go module；GitHub CI、branch protection 与交付 | 运行时 Git 网络、模型或业务 API |
| 消息与发布 | PR、required check 与 merge 记录 | release、package 发布、部署 |

## 6. Dependencies

- `modernc.org/sqlite v1.54.0`，canonical source 为 Go module proxy/module metadata。
- `golang.org/x/sys v0.47.0`，canonical source 为 Go module proxy/module metadata。
- `go.mod` 固定直接版本，`go.sum` 固定内容校验和；两者最低 Go 均为 `1.25.0`。
- 缺失时的失败语义：依赖下载、校验或构建失败即停止，不使用动态加载或 fallback。

## 7. Validation

- 可执行验证：`scripts/semantic-gate` 在 Linux 和 macOS 运行 `gofmt`、
  `git diff --check`、`go vet ./...`、`go test -count=1 -race ./...`、build 和设计第 9 节
  真实集成场景。
- 语义验收：Project identity、dirty exclusion、relink、restart、maintenance/replay、
  result digest 和目标仓库零变化。
- Target SHA 或 diff：绑定 PR adjacent base/head 和最终 cumulative head。
- Evidence 输出位置：测试输出、PR body、只读 Review 记录和最终交付说明。
- 明确未验证项：Docker 和 Nemeton 产品内通用 Gate engine 不在范围；Linux 与 macOS
  runtime 必须由 CI 真实验证。

## 8. Stop and rollback

- Stop conditions：需要改变 Accepted decision、超出 allowed paths、依赖不满足 Go
  1.25、无法保证 Git 只读、需要 M1 能力、基线发生无法安全吸收的变化，或主
  checkout 出现未知用户改动。
- Escalation：停止写入，保留 worktree、diff、失败命令和真实错误，向 Human 请求决定。
- Backup：`/mnt/data/coding/nemeton-backups/20260719-before-milestone-0-implementation`。
- Rollback steps：合并前保留或删除隔离 worktree并保留 branch；合并后使用新 revert
  commit，不改写 `main`。
- Rollback verification：核对 `main` SHA、工作树 clean、remote ref 和备份 bundle。

## 9. Delivery authorization

- 交付目标：commit、push、PR、merge 到 `main`，并同步本地主 checkout。
- 已授权动作：备份、隔离、实现、验证、只读 Review、文档对账、commit、push、
  创建 PR、运行 CI、设置 `main` required `semantic-gate`、merge 和本地同步。
- 需要再次确认的动作：仅限触发 stop condition 或需要扩大合同语义与路径。
